# SIM-003 – SQL Injection (T1190) - Detection Alert

**Symbolic ID:** LAB-SIM-004-SQLI-ALERT  
**MITRE Technique:** T1190 – Exploit Public-Facing Application  
**Severity:** Medium  
**Status:** Validated (IDS Layer)

---

## 🎯 Alert Purpose

This alert detects SQL Injection attempts against a vulnerable web application by identifying
malicious HTTP requests containing SQL logic observed by a network intrusion detection system (IDS).

The detection focuses on:
- SQL operators and logic embedded in HTTP parameters
- Abnormal or malformed web requests
- Exploit attempts against web-facing services

This alert represents a network-based detection suitable for SOC triage,
web attack investigation, and initial access analysis.

---

## 🔎 Detection Logic (Alert Source)

This alert is generated by Suricata running on Security Onion and reflects
real network traffic observed during SIM-004 execution.

Detection is based on:
- Inspection of HTTP payloads
- Identification of SQL keywords, operators, and comment markers
- Policy-based web attack signatures

> ⚠️ Detection occurs at the network layer.
> No application logs or database audit logs are required.

---

## 🧠 Detection Notes
- The alert is classified under ET WEB_SERVER
- The signature is generic and does not explicitly state “SQL Injection”
- Payload context and timing are required to confirm exploitation
- Alert confidence is derived from behavior + correlation, not signature name alone

This behavior is expected in real-world IDS deployments.

---

## ⏱️ Alert Timing & Generation
- Alert Type: IDS (Event-driven)
- Trigger Mechanism: Real-time packet inspection
- Timing: Immediate upon payload observation

No scheduling or polling interval applies, as detection occurs inline.

---

## 🚨 Trigger Conditions

The alert is generated when:
- An HTTP request contains SQL-related logic or malformed parameters
- Traffic matches Suricata web policy detection rules

A single confirmed request is sufficient to generate the alert.

---

## ⚠️ Severity Classification
- Severity Level: Medium

**Rationale:**  
SQL Injection represents an initial access technique that can lead to:
- Authentication bypass
- Data disclosure
- Credential access
- Further lateral movement

Severity may be escalated in production environments based on:
- Asset criticality
- Internet exposure
- Repeated attempts

# SIM-002 – DNS Tunneling Detection Alert

**Symbolic ID:** LAB-SIM-002-DNS-TUNNEL  
**MITRE Technique:** T1071.004 – Application Layer Protocol: DNS  
**Severity:** Medium  
**Status:** Deferred (SIEM Ingest Outage)  

---

## 🎯 Alert Purpose

This alert is designed to detect **potential DNS tunneling activity** by identifying
**suspicious or anomalous DNS query behavior** commonly associated with covert
command-and-control (C2) channels.

The detection focuses on:
- Abnormally structured DNS queries
- High-volume or repetitive DNS requests
- DNS usage inconsistent with standard resolution behavior

This alert represents a **network-layer detection** intended to provide early
visibility into stealthy C2 techniques once SIEM ingestion is operational.

---

## 🔎 Detection Logic (Alert Search)

This alert uses a **planned detection query** targeting DNS events generated by
Suricata and ingested into the SIEM. The logic reflects **validated network traffic**
observed during lab execution, despite the current ingest outage.

```lucene
event.dataset:"suricata.dns" AND dns.question.name:*
```
Detection Notes:
- Suricata DNS events are treated as the authoritative network signal
- Query logic is intentionally broad to support initial tunneling detection
- Refinement (entropy, length, frequency analysis) is planned post-ingest recovery
- Detection logic is preserved for future activation once data flow is restored

## 🧭 Analyst Response Workflow (Post-Trigger)

When this alert fires, an analyst should:
1. Identify the source host generating DNS queries
2. Review DNS query structure and frequency
3. Assess entropy or encoded patterns in query names
4. Correlate with endpoint process activity
5. Check for outbound connections or beaconing behavior
6. Validate against known tunneling tools or patterns
7. Document findings in the incident record
